# 레퍼런스 UI 분석

## 분석 목적

외부 운영형 RAG 서비스의 화면 구조를 분석하여
ContextHub UI 설계에 적용할 패턴과 건너뛸 패턴을 분류한다.

---

## 1. 전체 레이아웃 패턴

### 관찰

```
┌────────┬──────────────────────────┬──────────┐
│ 사이드바│       메인 콘텐츠         │ 우측패널  │
│ (고정) │  (검색 / 채팅 / 관리)    │ (필터/요약)│
│ 초록계열│       흰색/연회색         │ 연회색    │
└────────┴──────────────────────────┴──────────┘
```

- 사이드바: 아이콘 + 텍스트 메뉴, 고정 폭, 브랜드 컬러(초록계열)
- 메인: 검색/챗봇 중심, 카드 기반 레이아웃
- 우측: 필터 패널 또는 검색 결과 요약, 검색 중에도 유지

### ContextHub 적용 방향

3-panel 레이아웃 채택. 사이드바는 `w-60` 고정, 우측 패널은 `w-80` 고정.
브랜드 컬러는 ContextHub 기준으로 별도 결정 (레퍼런스 초록 그대로 쓰지 않음).

---

## 2. 에이전트 선택 패턴

### 관찰

- 좌측 상단에 현재 선택된 에이전트명 표시 ("판매예규 에이전트")
- 드롭다운 형태로 업무별 에이전트 전환 가능
- 에이전트별로 지식 DB, 권한, 필터 기본값이 달라짐

### ContextHub 적용 방향

| 레퍼런스 | ContextHub |
|---------|-----------|
| 판매예규 에이전트 | NAS RAG 에이전트 (현재 유일) |
| 계약관리 에이전트 | 향후: 로그 분석, 표준 검토 에이전트 |
| 드롭다운 전환 | MVP에서는 단일 에이전트, Phase 3에서 AgentRouter 연동 |

MVP에서는 에이전트 드롭다운 자리만 잡아두고, 선택지 1개(고정)로 시작.

## 3. 검색 필터 패턴

### 관찰

- 검색창 아래에 필터 버튼 배열
- 필터 항목: 지식 DB, 기준일/유효일, 상품명, 상품 코드, 파일명
- 도메인 특화 필터가 많음 (보험 상품 등)

### ContextHub 적용 방향

| 레퍼런스 필터 | ContextHub 대응 |
|-------------|----------------|
| 지식 DB | 프로젝트(project_key) / 경로(access_scope) |
| 파일명 | 파일명 검색 |
| 기준일/유효일 | 색인일(indexed_at) 범위 |
| 상품명/코드 | MVP 제외 (도메인 특화) |

MVP 필터: 프로젝트, 파일 유형(PDF/DOCX/HWP), 권한 범위(PUBLIC/DEPT)

## 4. 검색 진행 상태 패널 (Retrieval Progress)

### 관찰 — 핵심 UX 차별점

```
인텔리전트 검색
─────────────────────
✅ 1) 검색 필터를 적용합니다.
   지식 DB: 판매예규 DB
   유효일: 2026-01-01
   검색어: 보험료 납입 유예
✅ 2) 관련 내용을 검색하고 있습니다.
⏳ 3) 읽어오기
   판매예규_2026.pdf
   계약관련내규_v3.pdf
⏳ 4) 검색 내용 중 관련 내용을 확인합니다.
⏳ 5) 요약하기
   검색 결과 5건 중 상위 5건을 선별했습니다.
```

**이 패턴이 중요한 이유:**
RAG가 "블랙박스"가 아님을 사용자에게 보여주는 가장 효과적인 UX.
"어떤 문서를 읽고 있는지"가 보이면 사용자 신뢰가 높아진다.

### ContextHub 적용 방향

ContextHub의 단계 구조에 맞게 재정의:

```
1) 질문을 분석합니다.
   → normalization_applied, retrieval_query 표시
2) 관련 문서를 검색합니다.
   → SearchClient.search() 진행 중
3) 문서를 읽어옵니다.
   → 검색된 문서명 목록 표시 (chunk_ids 기반)
4) 답변을 생성합니다.
   → LLM 호출 중
5) 완료
   → X개 문서, Y개 섹션 참조
```

## 5. 답변 + 출처 패턴

### 관찰

- 답변 아래 피드백 (복사 / 좋아요 / 싫어요)
- 출처: PDF 아이콘 + 문서명 + 지식 DB 태그, 5개 내외
- 유사질문 칩 (연관 질문 제안)

### ContextHub 적용 방향

| 기능 | MVP | 향후 |
|------|-----|------|
| 답변 복사 버튼 | ✅ | — |
| 출처 목록 | ✅ | — |
| 좋아요/싫어요 | ❌ | Phase 2 |
| 유사질문 제안 | ❌ | Phase 3 (LLM 기반) |

## 6. 문서 상세 패널 패턴

### 관찰

- 문서 클릭 → PDF 뷰어 오픈
- 좌측: PDF 본문, 우측: 문서 정보(지식 DB, 파일명, 크기) + 관련 페이지 목록

### ContextHub 적용 방향

MVP에서는 **PDF 뷰어 없이 Chunk 상세 Side Panel로 대체**.

```
문서 클릭 →
  우측 슬라이드 패널 열림
  - 파일명, 경로, 권한, 색인일
  - 매칭 청크 목록 (section_title + chunk_text 첫 200자)
  - 점수 표시
```

PDF 뷰어는 Phase 3 이후 (NAS 파일 직접 서빙 또는 별도 뷰어 연동 필요).

## 7. 관리자 화면 패턴

### 관찰된 메뉴 구조

```
사용자 / 그룹 / 관리자
커넥터 / 워크스페이스 설정 / 공지사항
에이전트 / 템플릿 관리
시스템 설정 / 사용자 설정 / 연동
릴리즈 / 고급
```

### ContextHub 적용 방향 (3단계)

| Phase | 관리자 메뉴 |
|-------|-----------|
| MVP (1차) | 에이전트, 문서 현황, LLM 설정 |
| 2차 | 데이터 수집 스케줄러, 검색 품질 설정 |
| 3차 | 가드레일, Reranker, 통계 대시보드 |

---

## 8. ContextHub에 채택 / 제외 결정

### 채택

| 패턴 | 이유 |
|------|------|
| 3-panel 레이아웃 | 탐색-선택-생성 흐름에 최적 |
| 에이전트 드롭다운 (자리만) | 멀티에이전트 확장 포인트 |
| Retrieval Progress 패널 | RAG 신뢰성 확보의 핵심 UX |
| 출처 목록 | 이미 API에서 지원 |
| 문서 카드 + 점수 바 | `/discover` API 기반 |
| Chunk 상세 Side Panel | PDF 뷰어 대체 |

### 제외 (MVP)

| 패턴 | 이유 |
|------|------|
| PDF 뷰어 내장 | NAS 파일 서빙 미구현, 복잡도 과다 |
| 좋아요/싫어요 피드백 | 피드백 저장 DB 미설계 |
| 유사질문 자동 생성 | LLM 추가 호출 필요 |
| 인기 검색어 | 검색 이력 수집 미구현 |
| 사용자/그룹 관리 | AD/LDAP 미연동 단계 |
| 가드레일 | Phase 3 |
